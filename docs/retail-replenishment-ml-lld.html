Testing

1. Model accuracy

  • Rolling-origin backtesting over past seasons, holidays and promos.
  • MAPE and WAPE per SKU and per SKU cluster, plus bias; WAPE preferred for slow movers.
  • Time-based holdout set; compare against a naive seasonal baseline.
  • Business metrics in simulation: stockout hours avoided and over-order units.

2. Drift monitoring

  • SageMaker Model Monitor or Azure ML data drift on features and predictions.
  • Track live forecast error once actual sales arrive; CloudWatch or Azure Monitor alarms on thresholds.
  • Drift alarm triggers retraining through the pipeline, never a silent model swap.

3. Load testing

  • k6 or Locust against the endpoint and decision service (example: all stores in one hourly window).
  • Check endpoint autoscaling, Lambda or Functions concurrency, and DynamoDB or Cosmos DB throughput.
  • Validate P50, P90 and P99 against the table with X-Ray or Application Insights traces.

4. Guardrail correctness

  • Capacity at just below, at and above max; above must block.
  • Reserved-SKU pulls must block, including partial quantities.
  • Fail closed on missing or stale capacity, stock, reservation or forecast data.
  • Golden set of decisions that must never change result.

5. CI and model validation gate

  • pytest: feature transforms, reorder point and safety stock math, guardrails, with fixtures for SKUs, shelves and sales histories.
  • Model validation gate: a new model is registered only if backtest WAPE beats the current model and the baseline; otherwise deploy stops.
  • Pipeline: CodePipeline with CodeBuild and SageMaker Pipelines, or Azure DevOps or GitHub Actions with Azure ML pipelines; results to the CI dashboard and CloudWatch or Azure Monitor.
